## 3. 回滚问题的说明与修复 / The rollback issue and its fix

**复核指出的问题 / Issue raised in review**：
运行记录中成功的 eq_rollback 返回了多频段参数

```json
"rolled_back_to": {"gain_b1": 2.86, "log_freq_b1": 68.73,
                   "gain_b4": -0.24, "log_freq_b4": 5064.29,
                   "gain_b7": 2.11, "log_freq_b7": 234.69}
```

而 v1.0.0 提交的 `scripts/session_tool.py` 在回滚写回时硬编码了
单频段键名（`params["gain_db"]` / `params["freq_hz"]`），二者无法对应。
The v1.0.0 rollback write-back hardcoded single-band keys
(`params["gain_db"]` / `params["freq_hz"]`), which cannot address
the multi-band snapshot above.

**原因 / Root cause**：
会话快照有两种键名约定（见 `core/session_manager.py`）——
任务开始基线用控制键（`gain_bN` / `log_freq_bN`），确认的候选
用人性化键（`gain_bN` / `freq_bN`）；旧写回代码只认识已废弃的
单频段键名，遇到多频段快照会抛 KeyError。
Snapshots use two key conventions (see `core/session_manager.py`):
baseline uses control keys (`gain_bN` / `log_freq_bN`), confirmed
candidates use human keys (`gain_bN` / `freq_bN`). The old write-back
only knew the retired single-band names and raised KeyError on
multi-band snapshots.

**修复（change-70）/ Fix (change-70)**：
`scripts/session_tool.py::_write_back_params()` 改为遍历
`build_control_params(eq_cfg)` 逐频段写回：对每个频段同时尝试
人性化键与控制键（`freq_bN` ↔ `log_freq_bN`），两种快照都能
正确写回 FL。另将写回逻辑整体包入 try 块，异常不再泄漏
traceback，一律转为干净 JSON（`{"ok": false, ...}`）。
`_write_back_params()` now iterates `build_control_params(eq_cfg)`
per band, accepting both human (`freq_bN`) and control
(`log_freq_bN`) keys, so both snapshot conventions write back
correctly. All exceptions are converted to clean JSON.

  （`pytest tests/test_session_tool.py` 全过）。
  Regression tests cover multi-band rollback write-back.
- 运行记录中 `rolled_back_to` 的键名与修复后的代码读取的键名
  逐字一致。
  The `rolled_back_to` keys in the record match the fixed code's
